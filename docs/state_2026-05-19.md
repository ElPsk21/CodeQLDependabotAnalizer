# Estado del Proyecto - 19 de Mayo de 2026

## Resumen General
La aplicación se encuentra en un estado funcional avanzado. El objetivo principal de integrar análisis de seguridad de código (CodeQL) en una interfaz gráfica nativa mediante `zero-native` ha alcanzado un hito crítico: ahora permite no solo la ejecución y resumen de vulnerabilidades, sino también la exploración interactiva y previsualización de los fragmentos de código fuente asociados a cada hallazgo.

## Arquitectura Actual
* **Backend (Zig 0.16.0)**: 
  * `src/bridge.zig` actúa como el puente principal de IPC. Orquesta llamadas a la CLI de CodeQL para crear bases de datos y analizar proyectos en segundo plano.
  * Lee archivos locales para extraer snippets precisos del código fuente. Se implementó un codificador JSON manual (`escapeJsonString`) para evadir los continuos cambios de la API estándar de Zig, garantizando solidez.
* **Frontend (React/Vite)**: 
  * Se apoya en una UI dinámica que procesa los archivos SARIF (entregados en un sobre JSON).
  * Panel de detalles con caché para fragmentos (snippets) evitando llamadas innecesarias (o infinitas) y gestionando la reactividad limpiamente.
* **Zero-Native IPC**:
  * Utilizado para transmitir comandos (`codeql.runScan`, `codeql.readSnippet`) y eventos del sistema como logs y notificaciones de progreso.

## Cambios Recientes
* **Corrección de Renderizado de Snippets**: Se refactorizó la lógica del caché en React para evitar bucles infinitos en los `useEffect` de renderizado.
* **Fix Definitivo en Comunicación IPC**: Se solucionó el problema crítico donde la UI fallaba silenciosamente al no poder leer los snippets del backend. Esto se resolvió incrustando el código fuente en un payload JSON correctamente escapado y desempaquetándolo en JavaScript.
* **Limpieza de Proyecto**: Se eliminaron todos los binarios de depuración temporales, *scripts* aislados de test y residuos innecesarios de las sesiones anteriores. El proyecto quedó estructurado y limpio.
* **Documentación**: Se registró el caso técnico de solución del puente IPC en `docs/fix_snippet_json_ipc.md`.

## Conocimiento Acumulado y Limitaciones Conocidas
* **Memory Leaks Aislados**: El sistema base en `main.zig` al inicializar los handlers `zero_native.bridge.AsyncHandler` (en `getDispatcher`) refleja fugas de memoria al cerrarse la aplicación (reportadas por el `DebugAllocator`). Estos ocurren en la finalización de la app y no suponen un riesgo real de desbordamiento en tiempo de ejecución, por lo que su atención es de baja prioridad.
* **Compatibilidad Estándar de Zig**: Se ha comprobado que el sistema de paquetes base y la API `std` (específicamente `std.json` y `std.ArrayList`) difieren agresivamente en la rama "master" (0.16.0) instalada (Snap), por lo cual el código interactuando de forma nativa prescindirá en lo posible de APIs inestables.
